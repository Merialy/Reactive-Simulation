# ⚡ Симулятор моделі реактивності

Програмне забезпечення для розрахунку показників реактивності бортових обчислювачів аерокосмічних літальних апаратів.
Магістерська робота, Національний аерокосмічний університет «Харківський авіаційний інститут» (ХАІ).

Програма імітує, як бортовий обчислювач реагує на події: переривання надходять, стають у черги, обробляються за
пріоритетами і встигають або не встигають до свого дедлайну. За результатами кількох незалежних прогонів вона
рахує показники реактивності з 95 % довірчими інтервалами і пояснює їх простими словами.

---

## Можливості

* **Два режими.**
  * *Серія сценаріїв* — таблиця параметрів з Excel: кожен стовпець — сценарій з двома типами подій (ЖРЧ і МРЧ).
  * *Сценарій з типами подій* — JSON-файл з будь-якою кількістю типів подій і параметрами платформи
    (такти, частота процесора). Приклад — бортовий обчислювач «Боривітер».
* **Модель:** черга обробника переривань Q0 (FIFO), черги вторинної обробки QH (ЖРЧ) і QS (МРЧ),
  витіснення з дообслуговуванням, дискретно-подійне моделювання.
* **Відмови:** шторм хибних переривань і перевищення WCET на заданому інтервалі часу.
* **Фонові задачі:** найнижчий пріоритет, критичні секції з вимкненими перериваннями (t_id),
  перемикання контексту (t_cs).
* **Показники:**
  * 18 основних показників серії;
  * для кожного типу подій — час реакції (середній, WCRT, 95-й і 99-й перцентилі), ймовірність порушення
    дедлайну, джиттер, найдовша серія пропусків, коефіцієнт готовності, час блокування;
  * перевірка обмеження weakly hard «m з n»;
  * системні — U, H = 1 − U, U_os, η, максимальні довжини черг, показники фонових задач.
* **Порівняння з теорією:** три наближені формули теорії масового обслуговування (Поллачек–Хінчин, Кобгем,
  абсолютний пріоритет) поруч з результатом моделювання.
* **Статистика:** R прогонів із seed, seed + 1, …; середнє ± 95 % довірчий інтервал за Стьюдентом.
  Прогони виконуються паралельно, а результат не залежить від кількості ядер процесора.
* **Інтерфейс (Qt / PySide6):** висновки простими словами, графіки, експорт в Excel і PNG,
  світла і темна теми, українська та англійська мови.
* **Збереження:** MongoDB (без сервера — JSON-файли) без дублікатів; історія, пошук і порівняння результатів.

## Встановлення і запуск

Потрібен Python 3.10 або новіший.

```
pip install -r requirements-gui.txt
python app.py
```

На Windows ярлик на робочому столі (без вікна консолі) створює `tools\create_shortcut.bat`.

## Як користуватися

| Сторінка | Що робить |
|---|---|
| Початок | Схема моделі, кроки роботи, останні збережені результати |
| Серія сценаріїв | Таблиця параметрів: відкрити або зберегти .xlsx, редагувати, перевірка кожної комірки, завантаження U → «Запустити серію» |
| Типи подій і відмови | Готові сценарії, типи подій, платформа, відмови, фонові задачі, «Коротко про сценарій» → «Запустити» |
| Результати | Висновок простими словами, таблиці показників (± 95 % ДІ), системні й додаткові показники, порівняння з теорією, експорт в Excel, збереження в базу |
| Графіки | Будь-який показник від будь-якого параметра; час реакції за типами подій і в часі, з інтервалами відмов |
| Історія | Збережені результати: пошук, відкриття, порівняння, видалення |

Ліворуч унизу — кількість прогонів **R** (1…200) і **seed** (≥ 0), тема і мова.

Одиниці виміру: час — **мілісекунди**, інтенсивності — **події за мілісекунду** (1 мс⁻¹ = 1000 подій/с).

Докладний опис роботи програми з покроковим розбором прикладу — `docs/Як_працює_програма_v4.7.docx`.

## Формат сценарію (JSON)

Приклади — у папці `scenarios/`:

| Файл | Сценарій |
|---|---|
| `base_two_types.json` | Базовий сценарій статті: 2 типи подій |
| `boryviter_adcs.json` | «Боривітер»: 6 типів подій, без відмов |
| `boryviter_fault_storm.json` | «Боривітер» + шторм переривань UART |
| `boryviter_fault_wcet.json` | «Боривітер» + повільні датчики ADCS (перевищення WCET) |
| `boryviter_background.json` | «Боривітер» + фонові задачі (запис логів на SD-карту) |

Для типу подій задаються клас `cls` (`HRT` / `SRT`), інтенсивність `rate`, WCET (`wcet_ms` або в тактах
`wcet_cycles`), дедлайн `deadline_ms`, за потреби обмеження «m з n» (`wh_m`, `wh_n`). Для платформи —
`f_clk_mhz`, `c_irq`, `c_core` (T = C / F_clk). Відмови і фонові задачі:

```json
"faults": [
  {"kind": "storm", "start_ms": 20000, "duration_ms": 5000, "rate": 20, "wcet_ms": 0.03},
  {"kind": "overrun", "start_ms": 20000, "duration_ms": 20000, "target": "ADCS: датчики",
   "probability": 0.3, "factor": 2.5}
],
"background": {"mode": "periodic", "interval_ms": 100, "work_ms": 20, "deadline_ms": 50,
               "t_cs_ms": 0.005, "crit_ms": 0.2, "crit_share": 0.1}
```

Випадкові числа відмов і фонових задач беруться з окремих генераторів. Тому з тим самим seed основні потоки
подій однакові, і різниця показників зумовлена саме відмовою або фоновими задачами.

## Командний рядок

```
python -m simulation.run_scenario scenarios/boryviter_adcs.json -R 5 --seed 42
python -m simulation.run_scenario scenarios/boryviter_fault_storm.json -R 5 --save --tag "серія Е1"
```

Перегляд сховища:

```
python -m storage.cli status
python -m storage.cli scenarios
python -m storage.cli results
python -m storage.cli show <id результату>
python -m storage.cli dedupe        # прибрати дублікати, збережені версією 3.0
```

## База даних

База `reactive_simulation`, колекції `scenarios` і `results`. Запуск MongoDB (потрібен Docker Desktop):

```
docker compose up -d
```

Якщо MongoDB недоступна, ті самі документи зберігаються в JSON-файли в папці `data/`.
Сценарій впізнається за вмістом (параметрами), результат — за набором «сценарій + R + seed + версія моделі»,
тому повторне збереження не створює дублікатів. Інший R чи seed — новий запис.
Адреса бази — `MONGO_URI` у `config.py` або змінна середовища `REACTIVE_MONGO_URI`.
Вміст зручно переглядати в MongoDB Compass (`mongodb://localhost:27017`).

## Тести

```
python -m pytest -q
```

60 тестів перевіряють: граничний випадок M/D/1 (формула Поллачека–Хінчина), закон збереження роботи,
гарантію обробки подій ЖРЧ, закон Літтла, однакові результати обох ядер, відмови, фонові задачі,
додаткові показники, відтворюваність, сховище і логіку інтерфейсу.

Самоперевірка інтерфейсу (проходить усі сторінки і зберігає знімки екрана в `docs/screens`):

```
python -m ui.selftest
```

Тести і розрахунки без встановлення Python — у контейнері:

```
docker compose run --rm sim
docker compose run --rm sim python -m simulation.run_scenario scenarios/boryviter_adcs.json -R 5 --save
```

## Структура проєкту

```
app.py                     запуск програми
config.py                  налаштування, версії, межі параметрів, адреса MongoDB
simulation/
  priority_simulator.py    ядро серії (2 типи подій, 18 показників)
  engine.py                ядро сценарію з типами подій, відмовами і фоновими задачами
  model.py                 опис сценарію, перевірка, JSON
  replications.py          R прогонів, довірчі інтервали, паралельний запуск
  extra_metrics.py         джиттер, (m, n), готовність, макс. черги
  analytic.py              формули теорії для порівняння
  validation.py            перевірка параметрів серії
  run_scenario.py          запуск з командного рядка
storage/                   MongoDB / JSON-файли, утиліта cli.py
ui/                        інтерфейс Qt: сторінки page_*.py, core.py (логіка без Qt), explain.py, теми, мови
scenarios/                 готові сценарії
tests/                     автоматичні тести
tools/create_shortcut.bat  ярлик на робочому столі (Windows)
docs/                      документація
```
