# ⚡ Симулятор моделі реактивності

Програмно-моделюючий комплекс (ПМК) для дослідження та імітаційного моделювання систем масового обслуговування (СМО) з пріоритетами.
Цей проєкт реалізує інструментальну складову для верифікації наукової моделі реактивності. Програма дозволяє перетворити теоретичні формули та описи на інтерактивний інструмент для проведення експериментів та аналізу результатів.

---

✨ Основні можливості

* **📁 Робота з даними:** Імпорт вхідних параметрів безпосередньо з Excel-файлів (.xlsx).
* **📊 Інтерактивне редагування:** Вбудована таблиця для корегування значень "на льоту".
* **⚙️ Симуляція:** Проведення розрахунків на основі моделі реактивності для складних черг.
* **📈 Візуалізація:** Генерація графіків залежностей параметрів системи (використовуючи Matplotlib).
* **💾 Експорт:** Збереження отриманих результатів та звітів назад у формат Excel.

---

🛠 Технологічний стек

Програма побудована на мові **Python** з використанням таких бібліотек:
* **Tkinter** — для побудови графічного інтерфейсу користувача (GUI).
* **Pandas** — для обробки та структурування даних.
* **Matplotlib** — для побудови наукових графіків.
* **NumPy** — для математичних обчислень.
* **Openpyxl** — для взаємодії з таблицями Excel.

🔬 Наукове призначення

Проєкт розроблений як додаток до наукової статті про дослідження динамічних систем. Використання даного симулятора дозволяє:
  1. Підтвердити теоретичні розрахунки моделі реактивності.
  2. Провести аналіз стійкості системи при зміні пріоритетів.
  3. Отримати візуальний матеріал для публікацій та доповідей.

Розроблено спеціально для наукових та прикладних досліджень у сфері СМО.

---

📏 Одиниці виміру

* час (s1, s2, s2b, D1, D2) – **мілісекунди**;
* інтенсивності (λ1, λ2) – **події за мілісекунду** (λ = 1 мс⁻¹ відповідає 1000 подій/с).

---

🔁 Повторні прогони та відтворюваність (версія 1.1)

На вкладці «Симуляція» задаються **кількість прогонів R** і **seed**. Для кожного сценарію
виконується R незалежних прогонів, у таблиці показується «середнє ± напівширина 95 % довірчого
інтервалу». Усі сценарії однієї серії моделюються з однаковими seed (метод загальних випадкових
чисел), тому однаковий запуск завжди дає однаковий результат.

Перед запуском параметри перевіряються: програма попереджає, якщо завантаження U ≥ 1,
дедлайн недосяжний (D < s1 + s2) або подія ЖРЧ не встигає обробитися до наступної.

✅ Тести верифікації моделі

```
python -m pytest -q
```

Тести перевіряють: граничний випадок M/D/1 (порівняння з формулою Поллачека–Хінчина),
закон збереження роботи, гарантію обробки подій ЖРЧ, закон Літтла, відтворюваність
і реакцію на некоректні параметри.

🧩 Сценарії з кількома типами подій (версія 2.0)

Окрім Excel-таблиці з 8 параметрів (один тип МРЧ + один тип ЖРЧ), модель підтримує сценарії
у форматі JSON з довільним списком типів подій і параметрами апаратної платформи.
Приклади – у папці `scenarios/`:

* `base_two_types.json` – базовий сценарій статті (те саме, що один стовпець Excel);
* `boryviter_adcs.json` – ілюстративний сценарій БО «Боривітер»: 3 типи ЖРЧ (ADCS, команди
  приводам) і 3 типи МРЧ (команди НКК, моніторинг EPS, телеметрія).

Для кожного типу задаються: клас (`HRT` / `SRT`), інтенсивність або частота (подій/мс), WCET
(у мс або в тактах `wcet_cycles`), дедлайн. Для платформи – тактова частота `f_clk_mhz`
і такти `c_irq` (ISR) та `c_core` (накладні витрати ОС), які перераховуються в час за
формулою T = C / F_clk.

Запуск з командного рядка:

```
python -m simulation.run_scenario scenarios/boryviter_adcs.json -R 5 --seed 42
```

Програма виводить для кожного типу подій середній, 95-й і 99-й перцентилі та максимальний
час реакції, ймовірність порушення дедлайну і завантаження (середнє ± 95 % ДІ).
Для сценарію з двома типами нове ядро дає ті самі результати, що й версія 1.x (перевіряється тестами).
